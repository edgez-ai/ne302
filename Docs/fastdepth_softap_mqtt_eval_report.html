NE302 FastDepth Depth Reporting over SoftAP MQTT — Evaluation Report

Document ID: NE302-EVAL-DEPTH-MQTT-2026-10 · Date: 2026-10-30
Platform: NeoEyes NE302 (STM32N6 + SiWx917) · App under test: v4.3.1.334 @ 0x70100000
Model: FastDepth 224 NYU Depth V2 INT8 · SoftAP MQTT interval ≈ 30 s · FastDepth 320: out of scope

Link usable SoftAP constrained 320 not shipped

One-line conclusion: SoftAP + a laptop-local MQTT broker can deliver FastDepth 224×224 grayscale depth about every 30 seconds for customer link verification. SoftAP is suitable for demo/provisioning, not high-rate production traffic. Depth quality does not match paper “Proposed2”. FastDepth 320 was cancelled and is not promised.

1. Goals and non-goals

Goals

  1. SoftAP-only topology: laptop joins device hotspot, opens web UI, points MQTT at SoftAP IPv4.
  2. Receive depth JSON + Base64 on the PC broker without STA/Ethernet same-subnet requirement.
  3. Keep SoftAP alive for multi-minute paced tests.
  4. Publish native grayscale at model resolution (224×224), not false-color in the payload.
  5. Document limits for acceptance.

Non-goals

  • Matching academic Proposed2 visuals or metrics.
  • FastDepth 320 or dual-slot 224/320 UX.
  • Changing default sleep/power policy except SoftAP teardown proven harmful to MQTT tests.
  • Continuous high-rate depth over SoftAP.

Root cause of SoftAP drops under load is primarily NPU + large MQTT contending with SiWx917 SoftAP, not only sleep defaults. Pacing + AP retain are required for a stable demo.

5. Test process

5.1 Preparation

  1. Flash App v4.3.1.334 to 0x70100000; FastDepth 224 in AI slot.
  2. Start MQTT broker on PC port 1883; start depth viewer/subscriber.
  3. Power device; join SoftAP NE302_…; note DHCP 192.168.10.x.

5.2 Connectivity

  1. Ping 192.168.10.10 — expect replies.
  2. Open http://192.168.10.10 — web UI loads.
  3. Negative: MQTT server = Ethernet IP (e.g. 192.168.1.86) → timeout (documents misconfig).
  4. Correct: MQTT server = SoftAP laptop IP (e.g. 192.168.10.101:1883) → connects.

5.3 Depth happy path

  1. Enable MQTT; broker shows client.
  2. ≥3 depth messages ≈ every 30 s (± jitter).
  3. Payload 224×224 grayscale Base64 (+ JSON metadata).
  4. SoftAP remains associated for ≥5 minutes under paced publish.

5.4 SoftAP without MQTT

Web-only SoftAP should stay up; FastDepth skipped so provisioning is not starved by NPU.

7. Depth quality

  • On-device model is lightweight FastDepth 224 INT8 (NYU lineage), not Proposed2.
  • Raw maps look very dark in naive 8-bit view; contrast stretch reveals coarse near/far structure.
  • Edges/fine geometry are weaker than paper figures — SoftAP vs STA does not change the neural estimate.
Acceptance guidance: gate on “MQTT delivers paced SoftAP depth”, not on paper screenshot equality.

9. Risks

  • SoftAP + NPU + large MQTT — demo only; prefer STA for operations.
  • Wrong MQTT IP (Ethernet vs SoftAP) — common false failure.
  • Near-black depth perception — educate on contrast; optional viewer stretch.
  • 320 expectation creep — explicitly cancelled.

10. Recommendations

  1. Customer accept SoftAP MQTT 224 gray ~30 s cadence + SoftAP hold.
  2. Deploy with STA + LAN broker for production cadences.
  3. Quality/resolution upgrades as a separate scoped project.
  4. Do not ship FastDepth 320 without a new SOW.
